Admin A2U

Envois App → User (Testnet) pour débloquer les App Wallets Mainnet (5 wallets uniques).

Prérequis serveur : Edge Function pi-a2u déployée + secrets PI_A2U_API_KEY, PI_APP_WALLET_SEED, DCS_ADMIN_SECRET. Voir le guide docs/a2u-testnet-5-wallets.md.

Parcours (ordre)

  1. 1. Develop Portal → app Testnet paire → App wallet + Server API Key.
  2. 2. Secrets Supabase + supabase functions deploy pi-a2u --no-verify-jwt.
  3. 3. 5 Pioneers ouvrent signin-testnet.html (Pi Browser) → Allow. (Évite la perte de ?piSandbox=1.)
  4. 4. Ici : secret admin → Vérifier → Progress → Envoyer A2U × 5 uids.
  5. 5. Retour app Mainnet → créer Outgoing + Incoming Multisig.
Progression : — / 5

Charge la progression après « Vérifier » ou « Rafraîchir progression ».

Accès

Connecté DCS + secret DCS_ADMIN_SECRET (Supabase Secrets). Jamais de seed wallet dans le navigateur.

—

Envoyer 1 A2U

Le destinataire doit s’être connecté à DCS via Pi en mode Testnet (?piSandbox=1 pour avoir un pi_uid. Répète avec 5 comptes / wallets différents. Montant min. 0.0000001.

Destinataires (Testnet vs Mainnet)

Badge Testnet = uid utilisable pour A2U. Badge Mainnet seul = fera user_not_found → envoyer le lien signin-testnet.html.

Paiements incomplets

Si Pi refuse un nouvel envoi (« ongoing payment »), annule ou complète d’abord.
